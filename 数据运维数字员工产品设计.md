## 面向Claude Code的工程化实现指南

## 一、产品概述

### 1.1 产品定位

本产品是"数据运维数字员工"系统的工程化实现版本，基于前后端分离架构，实现三大数字员工（数据质量稽核、根因分析、月账管理）的核心功能与可视化界面，供截图用于详细设计文档。

### 1.2 技术栈约定

```
前端：React 18 + TypeScript + Ant Design 5 + ECharts
后端：Python 3.11 + FastAPI + SQLAlchemy + Celery
数据库：MySQL 8.0
大模型：OpenAI兼容接口（可配置endpoint/model/api_key）
环境管理：Python venv虚拟环境
包管理：前端npm，后端pip
```

### 8.4 风险识别与应对

| 风险项 | 概率 | 影响 | 应对措施 |
|--------|------|------|----------|
| LLM推理延迟高，影响体验 | 中 | 高 | 流式输出；异步分析；缓存常见问题结果 |
| LLM输出不稳定/幻觉 | 中 | 高 | 结构化Prompt约束；Tool调用验证；人工审核关键结论 |

| RAG检索准确率不足 | 中 | 中 | 分块策略优化；混合检索(向量+关键词)；持续标注反馈 |

| 用户接受度低 | 中 | 中 | 渐进式上线；保留手工流程；培训与指导；收集反馈快速迭代 |

## 十、附录

### 10.1 术语表

| 术语 | 说明 |
|------|------|
| TDP | 公司内部统一数据处理平台，调度和执行ETL任务 |
| Agent | 基于LLM的智能体，能自主决策调用工具完成任务 |
| Tool/Function Calling | LLM调用外部工具/API的能力 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| CoT | Chain of Thought，思维链推理 |
| Prompt | 提示词，指导LLM生成特定输出的文本模板 |
| 根因分析(RCA) | Root Cause Analysis，找到问题根本原因 |
| 月账 | 每月固定执行的账务数据处理流程 |
| 账期(acct_month) | 数据所属的会计月份，如202512 |
| 数据血缘(Lineage) | 数据的来源、流转和加工关系链路 |
| 笛卡尔积 | 两表Join时未限定条件导致的数据膨胀 |
| OOM | Out Of Memory，内存溢出错误 |
| 数据倾斜 | 数据分布不均导致个别节点处理压力过大 |
| DAG | Directed Acyclic Graph，有向无环图，描述任务依赖关系 |
| SSE | Server-Sent Events，服务器向客户端推送事件的协议 |
| WebSocket | 全双工通信协议，支持服务器主动推送 |

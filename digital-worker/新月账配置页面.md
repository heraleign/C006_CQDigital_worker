## 10. 配置管理页面设计

### 10.1 路由补充

```
/config                → 配置中心入口（4个Tab）
/config/stages                   → 阶段配置
/config/milestones               → 里程碑配置
/config/work-plans               → 作业计划配置
/config/tasks                    → 任务配置
```

主导航增加两个入口：**作业管理**（原有下钻查看）、**配置管理**（新增）。

---

### 10.2 页面结构

配置中心使用 Ant Design `Tabs` 组件，4个Tab共用一个页面 `ConfigPage.tsx`：

```
ConfigPage
├── Tab: 作业阶段
├── Tab: 里程碑
├── Tab: 作业计划
└── Tab: 任务列表
```

---

### 10.3 各Tab交互设计

#### Tab1 - 作业阶段配置

| 列 | 类型 | 说明 |
|----|------|------|
| 名称 | 文本 | 如：用户作业 |
| 排序 | 数字 | 显示顺序 |
| 操作 | - | 编辑 / 删除 |

- 顶部「+ 新增阶段」按钮 → 行内编辑或 Modal 弹窗
- 删除前提示：该阶段下有 N 个里程碑，确认删除？（级联删除）

---

#### Tab2 - 里程碑配置

| 列 | 类型 | 说明 |
|----|------|------|
| 所属阶段 | Select筛选 | 顶部下拉筛选 |
| 名称 | 文本 | 如：前置作业-1号任务 |
| 排序 | 数字 | - |
| 操作 | - | 编辑 / 删除 |

- 顶部「所属阶段」下拉筛选（默认全部）
- 新增弹窗字段：所属阶段（必填 Select）、名称、排序

---

#### Tab3 - 作业计划配置

| 列 | 类型 | 说明 |
|----|------|------|
| 所属里程碑 | Select筛选 | 顶部联动筛选 |
| 序号 | 数字 | - |
| 计划名称 | 文本 | - |
| 时间点 | 文本 | 如：1日10:00 |
| 任务方式 | Tag | 人工 / 数字员工 |
| 是否系统任务 | Tag | 是 / 否 |
| 操作 | - | 编辑 / 解析任务 / 删除 |

顶部筛选区：**阶段 Select → 联动 → 里程碑 Select**

**新增/编辑弹窗字段：**
```
所属阶段（Select，必填）
所属里程碑（Select，必填，联动阶段）
序号
计划名称
时间点
任务方式（Radio: 人工 / 数字员工）
是否系统任务（Switch）
执行模板（TextArea，高度200px）
[解析任务预览] 按钮 → 调用 /api/parse-template → 在弹窗内展示解析结果表格
[保存并自动生成任务] / [仅保存计划]
```

---

#### Tab4 - 任务列表配置

| 列 | 类型 | 说明 |
|----|------|------|
| 所属作业计划 | Select筛选 | 三级联动筛选 |
| 排序 | 数字 | 可拖拽排序 |
| 任务类型 | Tag | 颜色区分 |
| 内容 | 文本（省略） | hover展示完整内容 |
| 操作 | - | 编辑 / 删除 |

顶部筛选区：**阶段 → 里程碑 → 作业计划**（三级联动 Select）

**新增/编辑弹窗字段：**
```
所属作业计划（三级联动Select，必填）
任务类型（Select: TDP_TASK / PUBLISH_MSG / MANUAL_OP / SQL_SCRIPT）
内容（TextArea）
排序
```

### 10.5 ConfigPage.tsx 骨架

```tsx
import { Tabs } from 'antd';
import StageConfigTab from '../components/StageConfigTab';
import MilestoneConfigTab from '../components/MilestoneConfigTab';
import WorkPlanConfigTab from '../components/WorkPlanConfigTab';
import TaskConfigTab from '../components/TaskConfigTab';

const ConfigPage = () => (
  <Tabs
    items={[
      { key: 'stages',     label: '作业阶段', children: <StageConfigTab /> },
      { key: 'milestones', label: '里程碑',   children: <MilestoneConfigTab /> },
      { key: 'workplans',  label: '作业计划', children: <WorkPlanConfigTab /> },
      { key: 'tasks',      label: '任务列表', children: <TaskConfigTab /> },
    ]}
  />
);
export default ConfigPage;
```

### 10.6 通用组件规范

每个 Tab 组件结构一致，复用以下模式：

```tsx
// 每个ConfigTab的标准结构
const XxxConfigTab = () => {
  // 1. 筛选区（顶部）
  // 2. 操作区（新增按钮，右侧对齐）
  // 3. Table（含分页，pageSize=20）
  // 4. Modal（新增/编辑共用，通过 editRecord 是否为 null 区分）
};
```

**删除确认统一用 `Modal.confirm`**，提示级联影响数量。

**表单校验规则：**
- 名称：必填，最长100字
- 所属上级：必填
- 排序：正整数，默认0

### 10.7 新增 API 接口（配置管理补充）

原有接口已覆盖 CRUD，补充以下两个：

```
# 级联删除提示前查询子项数量
GET /api/stages/{id}/summary        → { milestone_count, plan_count, task_count }
GET /api/milestones/{id}/summary    → { plan_count, task_count }
GET /api/work-plans/{id}/summary    → { task_count }

# 批量排序（拖拽后提交）
PUT /api/stages/reorder             → body: [{id, sort_order}]
PUT /api/milestones/reorder         → body: [{id, sort_order}]
PUT /api/work-plans/reorder         → body: [{id, sort_order}]
PUT /api/tasks/reorder              → body: [{id, sort_order}]
```
